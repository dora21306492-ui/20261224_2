關卡 1：精靈圖切格與靜止動畫
---------------

**任務**：畫面中央顯示角色，循環播放 stop.png 的 14 張圖，每張 100 毫秒。

**想一想**：`image()` 有 9 個參數，前 5 個管「畫在哪」，後 4 個管「從原圖切哪一塊」。

```javascript
let stopSheet;                 // 靜止精靈圖
let stopFrame = 0;             // 目前影格
let lastFrameTime = 0;         // 上次換格的時間
const stopFrameCount = 14;     // 影格數
const stopSheetWidth = 1955;   // 總寬
const stopSheetHeight = 212;   // 高
const frameDuration = 100;     // 每格 100 ms

function preload() {
  stopSheet = loadImage("1/stop/stop.png");
}

function setup() {
  createCanvas(windowWidth, windowHeight);
}

function draw() {
  background(0);
  if (millis() - lastFrameTime >= frameDuration) {
    lastFrameTime = millis();
    stopFrame = (stopFrame + 1) % stopFrameCount;   // 到最後一張後回到 0
  }
  const fw = stopSheetWidth / stopFrameCount;      // 單格寬
  image(stopSheet, width / 2 - fw / 2, height - stopSheetHeight,
        fw, stopSheetHeight, stopFrame * fw, 0, fw, stopSheetHeight);
}
```

**檢核清單**

- [x] 一次只看到一個完整角色，沒有半格（出招圖每格寬度不平均，我改成依透明間隙切格）
- [x] 動作速度穩定，不會快到看不清（用 `millis()` 控制每格時間）
- [x] 第 14 張後會回到第 1 張（我的待機動畫照自己的需求改成來回播放：1→最後一張→1）

**問答**：為什麼用 `millis()` 而不是每個 `draw()` 都換格？

> 我的回答：`draw()` 大約每秒執行 60 次，而且電腦快慢不同，次數也會不同。如果每次 `draw()` 都換格，動畫會快到看不清楚，在不同電腦上的速度也不一樣。用 `millis()` 記錄時間，每經過固定的毫秒數（例如 100ms）才換一格，速度就會穩定，也不受電腦效能影響。

關卡 2：跑步動畫與左右翻轉
--------------

**任務**：按住→鍵播放 run.png，先播第 1–12 張，之後重複第 5–12 張；按←鍵動作相同但圖片翻轉；放開方向鍵回到 stop.png。

**想一想**：程式的索引從 0 開始。「第 5 張」的索引是幾？「第 12 張」呢？

> 「第 5 張」的索引是 **4**，「第 12 張」的索引是 **11**。

請完成對照表（`runFrameCount` 是播放位置，不是圖片索引）：

|     |     |     |     |     |     |     |
| --- | --- | --- | --- | --- | --- | --- |
| 播放位置 | 0   | 11  | 12  | 13  | 19  | 下一步 |
| 圖片索引 | 0   | 11  | **4** | **5** | **11** | 回到位置 **12** |

```javascript
// 更新播放位置（放在 millis 判斷裡）
if (action === "stop") {
  stopFrame = (stopFrame + 1) % stopFrameCount;
} else if (runFrameCount < 19) {
  runFrameCount += 1;
} else {
  runFrameCount = 12;
}

// 換算成圖片索引
const runIndex = runFrameCount < 12 ? runFrameCount : 4 + ((runFrameCount - 12) % 8);

// 翻轉
push();
translate(characterX, 0);
if (direction === -1) {
  scale(-1, 1);
}
image(runSheet, -displayWidth / 2, height - displayHeight, displayWidth, displayHeight,
      runIndex * fw, 0, fw, runSheetHeight);
pop();

function keyReleased() {
  if (keyIsDown(RIGHT_ARROW)) { direction = 1; return false; }
  if (keyIsDown(LEFT_ARROW))  { direction = -1; return false; }
  action = "stop";
  direction = 0;
  return false;
}
```

- [x] 每次起跑都從第 1 張開始（切換動作時會把步數歸零）
- [x] 長按時不會一直重來（提示：`event.repeat`）：`keyPressed(event)` 開頭加上 `if (event && event.repeat) return false;`，長按時不會被誤判成「連按兩下」
- [x] 向左時角色翻轉，且沒有跑到畫面外（角色 1 用 `scale(-1, 1)` 翻轉，並用 `constrain` 限制在畫布內）

**問答**：翻轉後圖片的 x 為什麼要寫 `-displayWidth / 2`？

> 我的回答：`translate(characterX, 0)` 已經把原點移到角色中心，而 `scale(-1, 1)` 會以這個原點為中心左右鏡像。圖片從 `-displayWidth / 2` 畫到 `+displayWidth / 2`，中心剛好在原點，所以翻轉前後角色都在同一個位置。如果寫成 0，圖片會畫在原點右邊，翻轉後跑到左邊，角色會突然跳一下。

關卡 4–5：背景鏡頭與中央捲動
----------------

**任務**

1.  背景 bg/0.png 左右各複製一份，共 3 張無縫串接。
2.  角色在中央時：按→背景往左、按←背景往右，角色原地跑。
3.  背景到盡頭就停，改由角色走到視窗邊緣。
4.  角色不在中央時，要先走回中央，背景才開始捲動。

**想一想**：把 3 張背景想成一條長圖，`backgroundCameraX` 是鏡頭在長圖上的位置。鏡頭往右，背景看起來往哪移？

> 鏡頭往右，背景看起來會**往左**移動，就像坐在車上往右開，窗外的景物往後退。

```javascript
const tileWidth = (backgroundImage.width / backgroundImage.height) * height;
const maxCameraX = max(0, tileWidth * 3 - width);   // 鏡頭最右位置
backgroundCameraX = (tileWidth * 3 - width) / 2;    // 開場置中

for (let i = 0; i < 3; i++) {
  const x = i * tileWidth - backgroundCameraX;
  image(backgroundImage, x, 0, tileWidth, height);
}

// 角色在中央、按右鍵
const scrollDistance = min(remainingMovement, maxCameraX - backgroundCameraX);
backgroundCameraX += scrollDistance;
remainingMovement -= scrollDistance;
characterX = min(width - runDisplayWidth / 2, characterX + remainingMovement);
```

**畫畫看**：在下方用文字或截圖畫出「長圖」與「鏡頭」的關係，標出 0 與 maxCameraX。

> 我的圖：
>
> ```
> 長圖（3 張背景串接，總寬 = tileWidth × 3）
> ┌───────────────┬───────────────┬───────────────┐
> │   bg/0.png    │   bg/0.png    │   bg/0.png    │
> └───────────────┴───────────────┴───────────────┘
> ↑ x = 0                                         ↑ x = tileWidth × 3
>
> 鏡頭（視窗，寬 = width）：
> [=====鏡頭=====]                                    ← backgroundCameraX = 0（最左）
>                  [=====鏡頭=====]                   ← 開場：(tileWidth×3 − width) ÷ 2（置中）
>                                   [=====鏡頭=====]  ← backgroundCameraX = maxCameraX（最右，觸發閃電）
>
> maxCameraX = tileWidth × 3 − width（鏡頭右邊剛好貼齊長圖右邊，所以右邊不會露出黑色）
> ```

關卡 6：閃電與爆炸
----------

**任務**：背景到最右端時，在距離視窗右邊 1/4 寬的位置，由上往下打 3 次閃電（每次 1 秒），再在視窗底端播 1 次藍色爆炸（1 秒），不斷重複。

**完成時間軸**：

|     |     |     |     |     |
| --- | --- | --- | --- | --- |
| 時段 (ms) | 0–1000 | 1000–2000 | 2000–3000 | 3000–4000 |
| 畫面  | 第 1 次閃電 | 第 2 次閃電 | 第 3 次閃電 | 藍色爆炸（畫面底端） |
| strikeNumber | 0 | 1 | 2 | 3（不播雷聲） |

```javascript
const elapsed = millis() - lightningStartedAt;
const cycleElapsed = elapsed % 4000;               // 一個循環多久？
if (cycleElapsed < 3000) {                          // 閃電階段
  const frame = floor((cycleElapsed % 1000) / 1000 * 14);
  // 畫閃電：高 = height，從 y = 0 開始
} else {                                            // 爆炸階段
  const t = cycleElapsed - 3000;
  const frame = min(9, floor(t / 1000 * 10));
  // 畫爆炸：高 = height * 0.2，y = height - 高
}
```

> 我的回答：`width * 0.75`（從左邊算是 3/4 的位置，也就是距離右邊 1/4）

關卡 7–8：打雷音效與特效退場
----------------

**任務**

1.  每次閃電出現時播一次 `audio/chrysalyn-clean-dramatic-lightning-crash-547378.mp3`。
2.  背景開始往回捲時，閃電要跟著背景移動，慢慢退出畫面；完全離開後才停止特效與音效。

**想一想**：`draw()` 每秒執行 60 次，如果每次都 `play()` 會發生什麼事？怎麼讓一次閃電只響一次？

> 每秒會重複播放 60 次，聲音疊在一起變成爆音。解決方法是記錄「上一次響過的是第幾道閃電」，只有換到新的一道閃電時才播放。

```javascript
// 音效：每次閃電只響一次
const strikeNumber = floor(cycleElapsed / 1000);
if (strikeNumber < 3 && strikeNumber !== lastThunderStrike) {
  thunderSound.play();
  lastThunderStrike = strikeNumber;
}

// 觸發時記下「在背景上」的位置（世界座標）
lightningWorldX = backgroundCameraX + width * 0.75;

// 每格換算回畫面座標
const effectX = lightningWorldX - backgroundCameraX;

// 特效是否已完全離開畫面右側？
const effectHasExited = effectX - effectDisplayWidth / 2 > width;

// 音訊必須在使用者操作後啟用（放在 keyPressed 裡）
userStartAudio();
```

**問答**：為什麼不能直接用 `width * 0.75` 當閃電位置？

> 我的回答：`width * 0.75` 是「畫面座標」，永遠固定在視窗的同一個位置。背景往回捲的時候，閃電會停在原地不動，不會跟著背景退出畫面。要先記下閃電在背景長圖上的位置（世界座標 `lightningWorldX`），每一格再減掉鏡頭位置換算回畫面座標，閃電才會跟著背景移動。
